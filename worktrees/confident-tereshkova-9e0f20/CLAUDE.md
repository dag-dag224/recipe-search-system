# CLAUDE.md — このリポジトリでの作業ルール

余っている食材（全角カタカナ）から料理を探すWebアプリ。返答・コメント・ドキュメント・コミットメッセージは日本語で書く。

## 構成

ビルドなし・依存パッケージなしの静的サイト（HTML / CSS / 素のJS、ES Modules）。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 検索画面と追加画面（追加画面は `hidden` で切り替え） |
| `css/style.css` | 見た目 |
| `js/main.js` | 画面の操作・入力チェック（食材名は `^[ァ-ヶー]+$`） |
| `js/recipeData.js` | CSVを `fetch` で読み、`Map<食材名, 料理名[]>` を作る |
| `js/recipeSearch.js` | `RecipeSearch` クラス：検索・追加データの検証と反映 |
| `js/recipeStorage.js` | 追加レシピを `localStorage`（キー `recipeWeb.additionalRecipes.v1`）に保存・復元 |
| `data/ingredient_recipes.csv` | 元データ。1行目は必ず `食材名,料理名` |

- 追加したレシピはCSVには書き戻さず、その端末のブラウザーにだけ保存する。
- 料理名・材料名に半角カンマや改行は入れられない（CSVと保存形式を壊さないため）。この制約を変えるなら、`recipeSearch.js` と `recipeStorage.js` の検証を両方そろえる。
- `fetch` を使うので `file://` では動かない。ローカルサーバー経由で開く。

## 動かし方・確認

```powershell
# リポジトリ直下で
python -m http.server 8000
# → http://localhost:8000/ を開く
```

自動テストはまだない。変更したら実際にブラウザーで開き、少なくとも次を確かめてから「完了」と言う。確かめていないことは、確かめていないと書く。

- CSVが読み込まれ、検索欄が使えるようになる
- 例：「キャベツ」で結果が出る／ひらがな・空欄で案内が出る
- レシピを追加 → 再読み込みしても残っている
- スマホ幅（375px程度）で崩れない
- コンソールにエラーが出ていない

## 進め方

1. **main で直接作業しない。** 作業ごとにブランチ（`feature/…`、`fix/…`、`docs/…`、`chore/…`）を切り、GitHub で PR にしてから main に入れる。
2. **小さな修正以外は、コードの前に方針を1枚書く。** `docs/plans/YYYY-MM-DD-内容.md` に「作るもの・作らないもの・完成の基準・影響する画面やデータ」を書き、私が読んでOKを出してから実装する。
3. 方針を書いたら、実装に入る前に自分で一度評価する（抜け・矛盾・スマホ幅・アクセシビリティの考慮漏れ）。
4. コミットメッセージは「何を」より「なぜ」を書く。
5. 既存コードの書き方に合わせる：日本語コメント、4スペースインデント、ダブルクォート、画面の文言は利用者向けのやさしい日本語。

## 必ず確認してから行うこと

- `git push`、PR の作成、main へのマージ
- 依存パッケージ・ビルドツール・外部CDNの追加（今は「依存なし」を保っている）
- `data/ingredient_recipes.csv` の形式変更や大量の書き換え
- `localStorage` のキー名・保存形式の変更（既存利用者の追加データが読めなくなる。変えるなら移行処理も考える）
- ファイルの削除

## やってはいけないこと

- 秘密情報（APIキー・トークン・パスワード・`.env*`）をコミットしない。
- `git commit --no-verify` などでチェックを飛ばさない。
- ユーザー入力を `innerHTML` で画面に入れない。`textContent` を使う。
