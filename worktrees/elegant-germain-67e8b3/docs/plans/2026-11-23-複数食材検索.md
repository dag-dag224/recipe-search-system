# 方針：複数の食材でまとめて検索し、関連性の高い順に50件出す

- 日付：2026-11-23
- ブランチ：`feature/multi-ingredient-search`
- 状態：承認済み（2026-11-23）

## 背景

今の検索欄は食材を1つしか受け付けず、その食材を使う料理を全部（CSVの順で）出している。
余っている食材が何種類かあるとき、「手元の食材をなるべく多く使える料理」から順に見たい。

## 作るもの

### 1. 検索欄に複数の食材を入れられるようにする

- 区切りに使えるもの：半角カンマ `,`、読点 `、`、全角カンマ `，`、スペース（半角・全角）。
  例：`キャベツ,ニンジン`、`キャベツ、ニンジン`、`キャベツ ニンジン`
  - 追加画面は半角カンマだけを受け付けるが、検索は保存に関わらないので、打ちやすいように広めに受け付ける。
- 区切ったそれぞれの食材名が全角カタカナかどうかを確かめる。1つでも違えば検索せず、
  「『きゃべつ』は全角カタカナで入力してください。」のように**どの食材がだめか**を示す。
- 同じ食材を2回入れても1つとして扱う。
- 入れられる食材は**最大10個**まで。超えたら検索せずに案内を出す（下の「確認したいこと」参照）。
- 1つだけ入れたときは、今と同じように使える（結果の上限が50件になる点だけが変わる）。

### 2. 関連性の高い順に並べ、上位50件を出す

「関連性」は次の順で決める。

1. **入力した食材のうち、いくつを使う料理か**（多いほど上）。
2. 同じ数なら、**先に入力した食材を使う料理**を上にする（1番目に入れた食材を「一番使いたいもの」とみなす）。
3. それでも同じなら、今と同じCSVの順（追加したレシピは後ろ）。

- 入力した食材を1つでも使う料理を候補にする（全部使う料理だけに絞ると、ほとんど0件になるため）。
- 候補が50件を超えたら、上位50件だけを出す。

> データについて：CSVの料理の約6割（5,352件中3,143件）は材料が1つしか登録されていない。
> そのため「料理の全材料のうち、手元にある割合」で並べると、材料の少ない料理ばかりが上に来てしまう。
> 今回はこの割合は使わず、上の3つの基準だけにする。

### 3. 結果の表示

- 件数の案内：`「キャベツ・ニンジン」を使う料理：全83件のうち、関連性の高い50件を表示`
  （50件以下なら `…：12件`）。
- 料理名の下（または横）に、**入力した食材のうち使うもの**を小さく出す。
  例：`ロールキャベツ` ／ `使う食材：キャベツ・ニンジン（2/2）`
  - 分母は入力した食材の数（重複を除く。未登録の食材も数に入れる）。食材を1つだけ入れたときはこの行を出さない（今と同じ見た目にする）。
  - 食材名は入力した順に並べる。
- 料理名を押すとGoogle検索が開くのは今のまま。
- 登録されていない食材が混ざっていたら、残りの食材で検索し、
  「『○○』は登録されていない食材のため、検索に使いませんでした。」と添える。
  全部未登録なら今と同じく「該当する料理はありません」。

### 4. 画面の文言

- 検索欄の説明：「食材を**全角カタカナ**で入力してください。複数あるときは「,」「、」かスペースで区切ります。」
- プレースホルダー：`例：キャベツ,ニンジン`
- README の「食材から料理を探す」の節を新しい使い方に合わせて書き直す。

## 作らないもの

- 部分一致・前方一致（`キャベ` → `キャベツ`）や、ひらがなからカタカナへの自動変換。
- 「全部の食材を使う料理だけ」に絞る切り替え、並び順の切り替え。
- 51件目以降を見る「もっと見る」・ページ送り。
- 料理の全材料の表示（CSVに全材料がそろっていないため）。
- CSVの形式・`localStorage` の保存形式の変更（どちらも触らない）。

## 完成の基準

ローカルサーバー（`python -m http.server 8000`）でブラウザーを開き、次を確かめる。

- CSVが読み込まれ、検索欄が使えるようになる。
- `キャベツ` だけで今までどおり結果が出る（50件以下なら全件）。
- `キャベツ,ニンジン`、`キャベツ、ニンジン`、`キャベツ　ニンジン` が同じ結果になる。
- 両方を使う料理が先頭に並び、各料理に「使う食材（2/2）」などが出ている。
- 候補が50件を超える組み合わせで、50件で止まり「全○件のうち…50件」と出る。
- `キャベツ,きゃべつ` のようにひらがなが混ざると、どれがだめか案内が出て検索しない。空欄・区切りだけでも案内が出る。
- 未登録の食材が混ざると、残りで検索し、その旨が出る。
- レシピを追加 → その材料を含めて複数検索すると出てくる → 再読み込みしても残っている。
- スマホ幅（375px）で、長い食材リストや「使う食材」の行がはみ出さない。
- コンソールにエラーが出ていない。

自動テストはないので、並び順の判定は `RecipeSearch` に関数として切り出し、ブラウザーのコンソールからも数件確かめる。

## アクセシビリティ

- 結果欄は今の `aria-live="polite"` のまま。件数の案内文が先に読まれるよう、文の組み立ては今と同じ順にする。
- 「使う食材」は料理名のリンクの外に置き、リンク名が長くなりすぎないようにする。
- 入力エラーの案内は今と同じ `result-message` に出す。

## 確認したいこと（決めてほしい点）

1. **並び順の2番目の基準**（同じ数の食材を使う料理どうし）：「先に入力した食材を優先」でよいか。
   ほかの案：「料理に登録されている材料が少ない順（＝買い足しが少なそう）」。ただし上のデータの事情で、材料が1つだけの料理が上に偏りやすい。
2. **食材の上限10個**でよいか（上限なしでもよい）。
3. **区切り文字**：スペースや「、」も受け付ける案でよいか（半角カンマだけにそろえる案もある）。
