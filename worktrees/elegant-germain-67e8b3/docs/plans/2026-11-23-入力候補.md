# 方針：検索欄に食材名の入力候補を出す

- 日付：2026-11-23
- ブランチ：`feature/ingredient-suggestions`（`feature/multi-ingredient-search` から作成）
- 状態：承認済み（2026-11-23）。「確認したいこと」はすべて案のとおり（選んでも自動検索しない／検索時のひらがな自動変換は作らない／候補6件・1文字から）

## 背景

検索欄は全角カタカナしか受け付けない。初めて使う人は、ひらがなで打ってから
「全角カタカナで入力してください」と言われて困る。
打っている途中で登録済みの食材名を候補として出し、選ぶだけで正しいカタカナが入るようにする。

例：「にん」まで打つ → 候補に「ニンジン」「ニンニク」… → 「ニンジン」を選ぶ → 検索欄が「ニンジン」になる。
カタカナへの変換も、残りの文字を打つ必要もない。

## 作るもの

### 1. 候補の探し方

- 候補にするのは、**登録されている食材名だけ**（CSV＋このブラウザーで追加した食材）。
  選んだ食材では必ず料理が見つかる。レシピを追加すると、その材料もすぐ候補に出る。
- 入力を次のように直してから探す。
  - **ひらがなはカタカナに直す**（`にん` → `ニン`、`ゔ` → `ヴ`）。長音 `ー` はそのまま。
  - 前後の空白は無視する。
- 1文字から候補を出す。0文字なら候補は出さない。
- 一致の仕方と並び順：
  1. **前から一致**する食材（`ニン` → `ニンジン`）を先に出す。
  2. 次に、**途中に含む**食材（`ネギ` → `タマネギ`）を出す。
  3. 同じグループの中では、**使う料理の多い食材**を上にする（よく使う食材が先に来るように）。それも同じなら50音順。
- 候補は**最大6件**。それ以上あっても6件で切る（スマホでキーボードに隠れないように）。
- 入力に一致する食材がなければ、候補の枠は出さない。
- 入力がすでに登録済みの食材名そのもの（例：`ニンジン`）のときは、それも候補の先頭に出す（そのまま選べて害がない）。

### 2. 複数食材の入力との関係

- 検索欄は `キャベツ,にん` のように区切って複数入れられる（複数食材検索の機能）。
  候補は**最後の区切りより後ろ**（今打っている食材）だけを対象に出す。
- 区切りは複数食材検索と同じ（`,` `，` `、` スペース）。
- 候補を選ぶと、**最後の食材だけ**を選んだ食材名に置きかえる。前の部分は変えない。
  例：`キャベツ,にん` → 「ニンジン」を選ぶ → `キャベツ,ニンジン`
- すでに入力済みの食材は候補から外す（`キャベツ,きゃ` で「キャベツ」は出さない）。
- 選んだあと、区切り文字は自動で足さない（打った区切りがそのまま使える。勝手に `,` が付くと戸惑うため）。

### 3. 見た目と操作

- 候補は検索欄のすぐ下に、一覧として重ねて出す。各候補は「食材名」と、小さく「料理○件」。
- 操作：
  - **タップ・クリック**で選ぶ。
  - **↓ / ↑** で候補を移動、**Enter** で選ぶ。候補を選んでいないときの Enter は今までどおり検索。
  - **Esc** で候補を閉じる。
  - 検索欄から離れる（ほかの場所をタップ・Tab）と閉じる。
- 選んだあとは候補を閉じ、カーソルは検索欄に残す。**自動で検索はしない**（続けて別の食材を入れられるように）。
- 日本語入力（IME）で変換中の文字にも候補を出す（`にん` と打った時点で出る）。
  変換中の ↑↓・Enter は IME の操作なので、候補の操作には使わない（変換を確定したあとは使える）。
- スマホ幅（375px）：候補1件の高さは48px（タップしやすい大きさ。今のボタンと同じ）。横にはみ出さない。
- **パソコン（マウス操作の画面）では、候補を検索欄の上に出す**（2026-11-23 追記）。
  Windows の IME の予測変換の窓は入力位置のすぐ下に出て、下に出した候補を隠してしまうため。
  Webページから IME やその予測変換を止める方法はない（`ime-mode` は廃止、`inputmode` はスマホの画面キーボード用）。
  - 判定は CSS の `(hover: hover) and (pointer: fine)`。スマホ・タブレットは今までどおり下に出す（予測はキーボード上の帯に出るので重ならない）。
  - パソコンでは候補1件の高さを40pxにする。上に入りきらないときは、画面からはみ出す分の候補を減らす（最低3件）。
    3件も入らないときだけ、下に出す。
- 検索欄の説明文に「ひらがなで打つと、候補が出ます。」を1行足す。

### 4. アクセシビリティ

WAI-ARIA の「コンボボックス（リスト形式）」の形にする。

- 検索欄：`role="combobox"`、`aria-autocomplete="list"`、`aria-expanded`（開閉で切り替え）、
  `aria-controls`（候補一覧のid）、`aria-activedescendant`（↑↓で選んでいる候補のid）。
- 候補一覧：`role="listbox"`、各候補：`role="option"`、`aria-selected`。
- 候補の件数を読み上げ用に知らせる（見えない `aria-live="polite"` の領域に「候補が3件あります。上下キーで選べます。」）。
- 選んでいる候補は色だけでなく、枠線でも分かるようにする。
- 画面に入れる文字はすべて `textContent` を使う（`innerHTML` は使わない）。

## 作らないもの

- 検索ボタンを押したときに、ひらがなを自動でカタカナに直して検索すること（今は案内を出すだけ。下の「確認したいこと」参照）。
- 漢字（`人参`）・ローマ字（`ninjin`）・半角カナからの候補。
- 追加画面の材料名欄の候補（今回は検索画面だけ）。
- 一致した部分を太字にするなどの強調。
- 過去に検索した食材の履歴。
- CSV・`localStorage` の形式の変更（どちらも触らない）。

## 完成の基準

ローカルサーバー（`python -m http.server 8000`）でブラウザーを開き、次を確かめる。

- CSVが読み込まれ、検索欄が使えるようになる。読み込み中は候補が出ない。
- `にん` と打つと「ニンジン」などが出る。`ニン` でも同じ候補。選ぶと検索欄が `ニンジン` になり、検索ボタンで結果が出る。
- `ねぎ` で、前から一致するものが先、「タマネギ」など途中に含むものが後に並ぶ。6件を超えない。
- 一致しない文字（例：`ぬぬぬ`）では候補が出ない。空欄に戻すと消える。
- `キャベツ,にん` → 「ニンジン」を選ぶと `キャベツ,ニンジン` になる。「キャベツ」は候補に出ない。
- キーボードだけで：↓↑で移動、Enterで選択、Escで閉じる、候補なしのEnterで検索。
- IMEで変換中に候補が出て、変換中の Enter で候補が選ばれてしまわない。
- レシピを追加（新しい材料名で）→ 検索画面に戻ると、その材料が候補に出る → 再読み込みしても出る。
- これまでの確認（`キャベツ` で結果、ひらがな・空欄で案内、複数食材の並び）が変わっていない。
- スマホ幅（375px）で候補が崩れず、タップで選べる。
- コンソールにエラーが出ていない。

候補を探す処理は `RecipeSearch` のメソッドにし、ブラウザーのコンソールからも数件確かめる。

## 自分での見直し（書いたあとに確認したこと）

- **複数食材ブランチとの関係**：区切り文字を2か所で別々に定義するとずれるので、共通にする。
  このPRは複数食材検索のPRがマージされたあとに main へ入れる。
- **Enter の衝突**：候補を選んでいるときだけ Enter で候補を選び、それ以外はフォーム送信（検索）のまま。IME変換中（`isComposing`）は何もしない。
- **クリックと blur の順番**：検索欄から離れたら閉じる処理が先に動くと、候補のクリックが効かない。
  候補一覧の `pointerdown` で検索欄のフォーカスが外れないようにして防ぐ。
- **スマホ**：重ね表示なので、下の「検索」ボタンが候補に隠れる。候補を閉じれば押せる（選ぶ・Esc・欄外タップで閉じる）。件数を6件にしてキーボードとの重なりを減らす。
- **読み上げ**：候補が変わるたびに件数を読み上げると、1文字ごとにうるさい。件数が変わったときだけ文を更新する。
- **追加データが読めなかったとき**（保存データ破損）：CSVだけで検索できる状態なので、候補もCSVの食材だけで出る。追加ボタンが使えない今の動きは変えない。

## 確認したいこと（決めてほしい点）

1. **候補を選んだら、すぐ検索するか**：案は「選ぶだけ（検索はボタン）」。複数の食材を続けて入れやすいため。
   食材1つで使う人が多いなら「選んだらすぐ検索」も考えられる。
2. **検索ボタンを押したとき、ひらがなを自動でカタカナにして検索するか**：今回は作らない案（候補を選べば済むため）。
   入れてもよいなら、小さな追加で対応できる（その場合「にんじん」で検索ボタン→「ニンジン」で検索）。
3. **候補の件数6件、1文字から出す**でよいか。
